# 上海保险招标提醒（tender-alert）

定时抓取招标网站的新公告，筛出**上海单位采购保险服务**的公告，发邮件提醒。
同一条公告只提醒一次；同一条公告在多个网站转载时也只提醒一次。

需求见 [需求.md](需求.md)。

其他候选企业门户的调研见 [采购门户调研.md](采购门户调研.md)。浦发银行的门户返回加密数据，没有接入。

**关于综合采购**：这个栏目的搜索和详情页被网站 robots.txt 禁止抓取，所以程序只读列表页（采购公告、单一来源、变更公告），
每页间隔 4 秒，每个栏目每次最多翻 10 页（网站从第 11 页起弹滑块验证码），不打开详情页；遇到验证码就停下报错，不会尝试通过。
采购公告每天 100 条以上，而每次最多只能看最新 100 条，所以定时任务每天跑三次（10:00、15:00、22:00）；
每次运行之间一般新增 30–50 条，基本不会顶到 100 条上限，但长时间关机后补跑仍可能漏，日志里会提示「中间可能有遗漏」。
作为兜底，建议同时在「上海公共资源交易」官方 App 里订阅关键词「保险」。

**一次性补抓历史**：列表页翻不到开始运行之前的公告，所以**第一次正式运行**（不带 --dry-run）时，
会用网站搜索按关键词补齐最近 `lookback_days` 天的综合采购公告，之后不再使用搜索。
想重新补一次，删掉 `data/tender-alert.db` 即可（同时会重新提醒所有公告）。

**关于申通地铁**：这个网站的 robots.txt 写的是整站禁止抓取，**用户已明确授权忽略**（2026-10-31）。
它的数据接口有 `sign` 签名保护，程序**没有去破解签名**，而是用本机 Chrome/Edge 的无头模式打开一次公开首页，
从渲染后的页面里读公告标题和日期——相当于用浏览器正常浏览。每个栏目只有最新 10 条、没有历史搜索，
靠每天定时运行增量覆盖；列表里没有详情链接，邮件链接指向平台首页。**需要本机装有 Chrome 或 Edge。**

**没有覆盖的**：中国招标投标公共服务平台 https://ctbpsp.com （全国国企招标汇总；robots.txt 整站禁止抓取，详情页要验证码）。

## 第一次使用

```powershell
# 1. 安装依赖（已装好的话跳过）
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt

# 2. 配置邮箱：复制 .env.example 为 .env，填写发信邮箱、授权码、收件人
Copy-Item .env.example .env

# 3. 发一封测试邮件，确认邮箱配置正确
.\run.ps1 --test-mail

# 4. 正式运行一次
.\run.ps1
```

没有配置邮箱时，程序不会报错，而是把邮件存成网页放在 `previews/` 目录里，可以直接用浏览器打开看。

## 常用命令

```powershell
.\run.ps1                    # 正常运行：抓取 → 筛选 → 发邮件（没有新公告时是运行报告）
.\run.ps1 --dry-run          # 只生成邮件预览，不发送，也不改动数据库（随便试）
.\run.ps1 --days 7           # 临时把回看范围改成 7 天（默认 30 天，在 config.toml 里改）
.\run.ps1 --sources ccgp     # 只跑某个来源，多个用空格或逗号分隔
.\run.ps1 -v                 # 显示详细日志，包括被筛掉的公告标题（调关键词时用）
```

日志在 `logs/tender-alert.log`，已提醒过的公告记录在 `data/tender-alert.db`。

**往年续标与原中标公司标记**：每次准备发信提醒新公告时，程序会自动核查这个项目在**近 3 年**（兼容 1 年期及「2027-2029」这类 2–3 年期续保标）有没有发布过：建安工程一切险、工程质量潜在缺陷保险（IDI）等一次性工程险会自动标为「一次性工程险（跳过往年核查）」；可续保项目依次检索本地数据库、上海政采网、国企采购及各机构自有公开列表（中国银联、SMG、国际招标、东航、机场、国泰海通），找到上一轮结果或合同公告时会在邮件标题下方高亮标记**往年发布月份与曾经的中标公司**（附往年公告链接），并同步写入 `exports/历史命中公告.csv` 的「往年及原中标」列。

**全量存档**：除了保险提醒，程序还会把抓到的所有上海公告（不限保险、所有类型）存进数据库的 `archive` 表，开关是 config.toml 的 `[archive]`。所有来源都抓全量（只要上海），每次只抓上次成功之后的新公告，一轮大约存一两千条、3 到 4 分钟。

**历史结果**：每次正式运行结束后，会自动把所有筛中的公告导出到 `exports/历史命中公告.csv`，双击就能用 Excel 打开，可以排序、筛选（其他网站转载的重复公告不重复列出）。
如果当时这个文件正开在 Excel 里，本次不会更新，关掉后下次运行再更新。
要 JSON 格式（给别的程序用）：`.\run.ps1 --export-json`，生成 `exports/历史命中公告.json`。

**全量存档的 CSV**：按发布月份拆成多个文件，放在 `exports/全量存档/`（如 `2026-11.csv`），每次正式运行后只重写有变动的月份。列有发布日期、类型、公告类型、标题、采购单位、预算、截止/开标、来源、首次发现、链接。想全部重新导出：`.\run.ps1 --export-archive`。
想让所有公告重新提醒一遍，删掉 `data/tender-alert.db` 即可。

## 调整筛选规则

都在 [config.toml](config.toml) 里：关键词、排除词、要提醒的公告类型（招标/更正/结果/采购意向）、回看天数、启用的来源。
用 `.\run.ps1 --dry-run -v` 看哪些公告被筛掉了，再决定要不要加关键词。
改完立即生效，包括之前已经抓到、还没发出去的公告。

## 定时运行

```powershell
pwsh -File install-task.ps1   # 注册：每天 10:00、15:00、22:00 各运行一次
```

**不是每个来源每次都抓**：更新快的来源（上海政府采购网、综合采购、申通地铁、东航、中国政府采购网）三次都抓；更新慢的来源每天只抓一次，当天抓成功过，后面两次就跳过，邮件末尾的运行情况汇总里会算进「N 个今天已抓过」。哪些来源每天一次，在 config.toml 的 `once_a_day` 里改。用 `--sources` 点名的来源不受这个限制。

定时任务用 `pythonw.exe` 运行，不会弹出窗口，运行情况全部记在 `logs/tender-alert.log`。
电脑睡眠时到点会自己醒来运行，前提是 Windows 电源设置里「允许使用唤醒定时器」已启用（只在插电时启用就行）。
没能唤醒或关机了的话，开机后会补跑一次（综合采购除外，见上文「关于综合采购」）。
删除定时任务：`Unregister-ScheduledTask -TaskName TenderAlert -Confirm:$false`

## 出问题时

- **邮件发送失败**（授权码过期、网络断了）：日志里有原因，邮件内容另存到 `previews/`，没发出去的公告下次运行会重发。
- **某个来源抓取失败**（网站改版或临时限流）：日志里能看到原因。同一个来源连续失败 3 次（可在 config.toml 调整），会发一封告警邮件，修好之前不会重复告警。
中国政府采购网的搜索偶尔会提示「访问过于频繁」，一般下次运行就好了；每次搜索都覆盖整个回看范围，不会漏。
- **网站返回 429/503（限流）**：程序会自动放慢，对这个网站的请求间隔加倍（最多 60 秒），网站给了 Retry-After 就照它等（超过 2 分钟就放弃，下次再试）。
- **robots.txt 禁止**：每个请求发出前都会检查网站的 robots.txt（缓存 7 天，在 `data/robots_cache.json`），被禁止的请求不会发出，这个来源记为失败。用户授权的例外在 `tender_alert/robots.py` 的 `EXCEPTIONS` 里。

## 测试

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests
```

`tests/fixtures/` 里是各来源录下的真实响应，测试会不联网地回放一遍，检查解析结果正常。网站改版后回放测试会失败，确认代码改好后重新录一次：

```powershell
.\run.ps1 --dry-run --record   # 和普通试运行一样会真实访问各网站，不发信、不改数据库
```
